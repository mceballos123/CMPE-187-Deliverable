PROMPT:
What is the difference between an SNMP trap and an SNMP inform?

ANSWER:
SNMP traps and SNMP informs are both event-driven notifications sent from an SNMP agent (such as a router, switch, or server) to an SNMP manager (such as a network monitoring system) when something notable happens—like a link going down or high CPU usage.
The core difference comes down to delivery confirmation and reliability: an SNMP trap is "fire-and-forget" (no acknowledgment), whereas an SNMP inform requires the manager to send back an acknowledgment (InformResponse) and is retried if none arrives.
Side-by-Side Comparison
Feature SNMP Trap SNMP Inform
Acknowledgment No — sent once and forgotten by the agent. Yes — manager replies with an SNMP response PDU.
Retries None — if lost in transit, the event is missed. Configurable — agent retries up to a set count after a timeout.
Network & CPU Overhead Lower — one-way traffic, minimal state tracking. Higher — round-trip traffic plus agent retry/timeout logic.
SNMP Versions v1, v2c, and v3. v2c and v3 (not supported in SNMPv1).
UDP Port (Default) UDP 162 (manager listens). UDP 162 (manager listens; response goes back to agent's source port).
Best Use Case High-frequency, non-critical, or noisy alerts where occasional packet loss is acceptable. Critical alerts (e.g., hardware failure, security breach, link down) where guaranteed delivery matters.
How Each Works
SNMP Trap (Fire-and-Forget)
A monitored event occurs on the agent (e.g., an interface drops).
The agent builds a Trap PDU and sends it via UDP to the manager's port 162.
The agent moves on immediately—it does not wait for a reply or know whether the packet arrived.
SNMP Inform (Acknowledged Notification)
A monitored event occurs on the agent.
The agent sends an InformRequest PDU (carrying a request ID) to the manager's port 162.
If the manager receives it, it replies with a Response PDU containing the same request ID.
If the agent doesn't receive a response before its timeout expires, it retransmits the Inform up to its configured retry limit.
Practical Trade-Offs & Tuning Tips
Beware of retry storms: If a network link goes down or a manager is overwhelmed, unacknowledged Informs can trigger retries. Set sensible timeout and retry values so agents don't flood a congested network or slow down an overloaded NMS.
Match the importance of the event: Use Informs for high-value state changes (power supply failure, BGP session drop, unauthorized login attempt) and Traps for frequent telemetry or lower-severity notices where losing an occasional packet won't blind you.
Don't forget SNMPv3 security: Both Traps and Informs can use SNMPv3 authentication and encryption (authPriv), which is strongly recommended over v2c community strings on production networks.
