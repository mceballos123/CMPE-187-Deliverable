PROMPT:
How is an SNMP inform different from an SNMP trap?

ANSWER:
The main difference between an SNMP trap and an SNMP inform is that an inform requires an acknowledgment from the receiving SNMP manager, while a trap does not.
Both are used by network devices (routers, switches, firewalls, servers, etc.) to send event notifications to an SNMP management system.

How they work

The device sends a notification to the SNMP manager.
The manager receives it if the packet successfully arrives.
If the packet is lost, the device generally doesn't know.
No automatic retransmission occurs.
2. SNMP Inform
Network Device
Sends SNMP Inform
UDP 162 — notification
SNMP Manager
Receives and processes notification
SNMP Response — acknowledgment
Network Device
Receives acknowledgment
Delivery acknowledged
The device sends an inform notification.
The SNMP manager responds with an acknowledgment (SNMP Response PDU).
If the device doesn't receive the acknowledgment, it can retransmit the inform.
This makes informs more reliable, although it doesn't guarantee that an event was successfully acted upon.
Practical example
Imagine a switch detects that one of its interfaces has gone down.
Using a trap:
Switch sends an interface-down notification.
The monitoring server receives it.
If the packet gets lost, the monitoring server never knows about the event.
Using an inform:
Switch sends an interface-down notification.
The monitoring server receives it and acknowledges it.
If the acknowledgment is lost, the switch retransmits the notification.

Bottom line: A trap is fire-and-forget. An inform is acknowledged and can be retransmitted if the acknowledgment is missing.
One important detail: SNMP informs confirm receipt at the SNMP protocol level, not necessarily that an administrator has seen or resolved the alert.
